# Indexing and pagination
Derive indexes from actual WHERE/JOIN/ORDER BY patterns, not column names. Consider equality filters, ranges, ordering, selectivity and existing prefixes; verify via execution plans. Example candidate for tenant-scoped chronological listing: (tenant_id, created_at, id). Assess storage, write amplification, deployment locks and redundant indexes. Use uniqueness constraints for correctness where required.

Keyset example with descending order: WHERE tenant_id = :tenant AND (created_at < :time OR (created_at = :time AND id < :id)) ORDER BY created_at DESC, id DESC LIMIT :size. Bind parameters using driver syntax. Use matching non-null stable sort keys and unique tie-breaker. Cursor must encode the sort keys and be validated; never use it to authorize access. Preserve filters across pages. Offset remains reasonable for small lists and random page jumps. Avoid expensive exact total counts unless required. Define concurrent update/snapshot expectations.
