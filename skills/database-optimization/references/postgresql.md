# PostgreSQL
Use EXPLAIN first; for approved representative SELECTs use EXPLAIN (ANALYZE, BUFFERS). ANALYZE executes the statement. Review actual vs estimated rows, loops, buffers, sorts spilling to disk, and expensive scans. Sequential scans are not inherently bad. Use pg_stat_statements if available and authorized; compare normalized query frequency and total/mean time. Inspect pg_stat_activity and lock waits safely. Check autovacuum/statistics and bloat before assuming indexing is the answer. Evaluate B-tree composite/partial indexes, INCLUDE columns and appropriate GIN/BRIN only for matching workloads. Concurrent index creation has deployment constraints and cannot run inside a transaction block. Use approved migrations and monitor write overhead. Evaluate pooler compatibility with prepared statements and session features.
