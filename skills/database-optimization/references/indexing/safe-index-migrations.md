# Safe index migrations
Document target query, existing indexes, candidate DDL, expected benefit, constraint dependencies, size/write overhead and tests. Use project migration conventions and version-specific engine capabilities. Estimate build duration/disk/log/replica pressure; plan lock and statement timeouts, deployment window, monitoring and abort criteria. Test on representative staging. Obtain authorization before production execution. For replacement, build and validate the new index before removing the old where feasible; avoid dropping constraint-backed indexes. PostgreSQL concurrent builds need nontransactional migration handling and invalid-index cleanup planning. MySQL online DDL and SQL Server online/resumable options have restrictions; SQLite may block writers. Provide reversible DDL and recovery plan; rollback can itself be expensive. Verify plans, latency and write overhead after deployment.
