# Composite indexes
Choose key order from workload: equality-constrained keys often precede range/order keys, but reuse, selectivity, sort direction, collation and engine behavior matter. Example candidate: (property_id, status, check_in_date DESC, id DESC) for a property/status-scoped ordered list with stable pagination. A query omitting status may need a different strategy. Check leftmost prefixes and actual plans; some engines can use skip scans or combine indexes. Do not assume a composite index replaces all single-column indexes. Compare constraints, included columns and predicates.
