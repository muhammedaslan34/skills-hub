# Index maintenance
Monitor size, write amplification, page density/bloat, statistics freshness, vacuum or equivalent maintenance and lock waits. Diagnose actual symptoms before rebuilding. PostgreSQL: evaluate vacuum/statistics and supported reindex options; MySQL: evaluate InnoDB statistics and table maintenance impact; SQL Server: weigh page density, fragmentation and workload rather than fixed thresholds; SQLite: consider ANALYZE/PRAGMA optimize under approved maintenance procedures. Maintenance commands can write, lock and consume substantial disk/IO. Never run them as part of read-only audits.
